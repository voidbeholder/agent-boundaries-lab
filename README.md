# Границы агента — лаборатория

Локальный стенд к лекции об автономии и human-in-the-loop. **Живая LLM** выбирает инструменты; **harness** проверяет действия; инструменты изменяют **учебную систему заказов**. Денежные операции фиктивные. Модель не подменяется симулятором.

Python 3.11+, браузер, ключ OpenAI-совместимого API и модель с **нативной поддержкой tool calling**. Внешних Python-пакетов, Node.js и сборки интерфейса не требуется.

## Запуск

1. Скопируйте `.env.example` в `.env`.
2. Заполните `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL`.
3. Выполните из каталога репозитория:

```sh
python server.py
```

Откройте **http://127.0.0.1:8765**. Другой порт: `python server.py --port 8766`.

Настройки читаются при старте. После изменения `.env` перезапустите сервер. Переменные окружения имеют приоритет над `.env`. Ключ не передаётся браузеру и не включается в экспорт журнала; `.env` исключён из Git. Не помещайте ключи в запрос модели.

### OpenRouter и Hugging Face

| Поставщик | `LLM_BASE_URL` | `LLM_MODEL` |
|---|---|---|
| OpenRouter | `https://openrouter.ai/api/v1` | Точный идентификатор доступной модели с поддержкой tools; для бесплатного варианта проверьте его условия и идентификатор в каталоге |
| HF Inference Providers | `https://router.huggingface.co/v1` | Идентификатор модели/маршрута, доступного вашему токену и поддерживающего tools |
| Другой совместимый сервер | Адрес API до `/chat/completions`, обычно заканчивается `/v1` | Идентификатор вашей модели |

Совместимость проверяется по **Chat Completions**: `messages`, `tools`, `tool_choice`, `max_tokens`, ответ `tool_calls`, сообщения `role=tool` с `tool_call_id`. Адрес не должен уже включать `/chat/completions`. Клиент не делает скрытых повторов и не переключает модели/провайдеров сам.

«Есть модель на HF» не означает, что её можно бесплатно вызвать через hosted API. Бесплатность, доступность, квоты и поддержка tools зависят от маршрута и аккаунта. Стенд не выбирает платный fallback автоматически. Совместимость с конкретным провайдером нужно проверить коротким запуском перед занятием.

Официальные источники:

- [OpenRouter: tool calling и фильтр поддерживаемых моделей](https://openrouter.ai/docs/guides/features/tool-calling).
- [OpenRouter: бесплатные варианты](https://openrouter.ai/docs/guides/routing/model-variants/free).
- [HF: Chat Completion](https://huggingface.co/docs/inference-providers/tasks/chat-completion).

## Что показываем

Интерфейс разделён на диалог, журнал **модель → harness → инструмент → человек** и фактическое состояние заказов. Просматривайте аргументы и результаты в журнале, а не скрытые рассуждения модели. Текст ответа модели сам по себе не устанавливает успех.

Семь сценариев: обычный возврат; неопределённое намерение; временный сбой; документ с `CHECKERROR`; превышение полномочий; потеря ответа после записи; инструкция в примечании заказа. Сценарий меняет данные или поведение учебного сервиса. Решение, какой инструмент вызывать, принимает LLM, поэтому конкретная последовательность не гарантирована.

**Пять экспериментов для семинара**, без установки и программирования с нуля:

- Уточнить неясное поручение, затем отдельно согласовать запись. Сравнить два вида пауз.
- Отклонить возврат; попробовать отправить подтверждение с подменённой суммой. Запись не должна состояться.
- Уменьшить число ходов или время; запустить сбойный сценарий. Отличить ресурсную остановку от решения модели закончить.
- Сравнить слова «готово» с `CHECKERROR`, `REGISTERED` и `money_sent=false`.
- Получить пакет передачи и нажать «Я оператор: принять задачу». Отличить постановку на передачу от принятия управления.

Результат участника: «что предложила модель / что разрешил harness / что изменилось / кто действует дальше». Можно скачать журнал JSON каждого запуска.

## Архитектура для разбора

```text
Браузер → локальный сервер → harness → OpenAI-совместимый API
                               ↓             ↑
                       локальные инструменты
                               ↓
                       учебные заказы и заявки
```

- `lab/model.py` — HTTP-клиент LLM, без бизнес-правил.
- `lab/tools.py` — описания инструментов, фиктивная система заказов и инъекции ошибок.
- `lab/harness.py` — цикл, разрешения, бюджеты, паузы, отказ, продолжение, проверка результата, передача.
- `server.py` — HTTP-интерфейс и фоновые запуски.
- `web/` — интерфейс без библиотек и внешних ресурсов.
- `tests/` — воспроизводимые проверки harness с тестовыми ответами; это не замена живой модели в приложении.

### Контракты

- `create_refund` требует актуального `prepare_refund` и отдельного согласия. Параметры и версия заказа должны совпасть; согласие имеет срок действия. Отказ завершает попытку, не отправляя модели задание найти обход.
- Суммы свыше 5 000 ₽ передаются оператору. Лимит — учебное правило, он не редактируется текстом запроса или кнопкой согласия.
- После неизвестного результата повтор записи блокируется до проверки статуса. Учебный сервис также не создаёт второй возврат по тому же заказу.
- `REGISTERED` — заявка зарегистрирована. Это не возврат денег. Внешних платёжных API нет.
- После передачи агент прекращает действия; нажатие оператором кнопки меняет владельца. Рабочее место оператора и обратная передача агенту пока не реализованы.
- Проверка результата относится к узкому кейсу регистрации возврата. Семантическую правильность произвольного пользовательского намерения harness не доказывает.

### Бюджеты и их границы

Счётчики действуют на всю сессию, включая продолжение после человека. Ход — HTTP-обращение к модели; исполнение — вызов инструмента системы заказов. Уточнение и передача учитываются в журнале, но не в счётчике бизнес-инструментов. Лимит повторов 2 означает исходную попытку и до двух повторов той же ошибки.

Активное время исключает ожидание человека. Перед запросом API timeout ограничивается оставшимся временем; после ответа бюджет проверяется ещё раз. Тайм-аут транспорта не гарантирует отмену уже выполняемого запроса у провайдера. Остановка в интерфейсе прекращает дальнейшие действия, но не отзывает уже отправленный запрос LLM и не откатывает выполненные инструменты.

Стоимость рассчитывается **после ответа** по `usage` и тарифам `LLM_INPUT_PRICE_PER_MILLION` / `LLM_OUTPUT_PRICE_PER_MILLION`. Тарифы задаёт преподаватель; это оценка без точного учёта скидок кеширования, дополнительных сборов и тарификации неуспешных запросов. Без обоих тарифов стоимость неизвестна и денежный лимит включить нельзя. Для бесплатного маршрута можно явно задать оба тарифа 0. Нулевой тариф не снимает квоты API.

Порог USD может быть превышен стоимостью последнего ответа: это демонстрация проверки после расхода, не строгий финансовый потолок. При денежном лимите и отсутствии usage приложение останавливается, поскольку не может учитывать расход. Для реального ограничения счёта нужны также настройки аккаунта провайдера.

## Проверка

```sh
python -m unittest discover -v
```

Тесты не требуют ключа и не делают внешних API-вызовов. Проверяется барьер записи, отказ, подмена/устаревание согласия, повтор после тайм-аута, бизнес-лимит, бюджеты и HTTP-протокол с локальным тестовым сервером. Успех этих тестов не доказывает качество выбранной LLM — его проверяют живыми сценариями.

## Границы первой версии

Только localhost, один преподаватель/участник на локальной копии. Аутентификации и общего многопользовательского кабинета нет. Сессии и чекпойнты находятся в памяти: перезапуск удаляет их. Журналы сохраняются только по кнопке экспорта. Это читаемый учебный harness, а не готовая инфраструктура платежей.

Следующие изменения при необходимости: постоянное хранение сессий, набор живых оценочных прогонов по моделям, управление пользовательскими ролями, строгий общий бюджет параллельных задач. Подробный минутный план семинара намеренно не задан.
